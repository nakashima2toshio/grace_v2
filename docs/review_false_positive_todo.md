## 3. 条文データの鮮度 — なぜ `--recreate` が必須だったか（✅ 2026-08-20 20:47 に解消）

> **結果**: `--recreate` 付きで再登録し、Qdrant 側 22 件 / 処理 22 件で一致。
> 以下は判断の根拠として残す。同じ状況（ルール本文を変えた後の再登録）では毎回必要になる。


`ec_ad_rules_anthropic` の登録は **2026-08-18T13:37:07**。それ以降に 3 件のルール本文が
変わっている。

```
8/18 登録時から変わったルール: 3 / 22 件
  yakki-01     description
  yakki-02     description/keywords
  policy-01    description
```

### ポイント ID は内容ハッシュ

`services/qdrant_service.py::build_points_for_qdrant`:

```python
# 内容ベースの決定的ID（位置非依存・再登録べき等）
pid = stable_point_id(_content_point_key(row, domain, source_file, start_index + i))
```

**本文が変われば ID も変わる。** つまり `--recreate` なしで再登録すると:

| | 件数 | 中身 |
|---|---|---|
| 変わっていない 19 件 | 19 | 同じ ID で上書き（問題なし） |
| 変わった 3 件（新） | 3 | **新しい ID で追加** |
| 変わった 3 件（旧） | 3 | **古い ID のまま残る** |
| 合計 | **25** | 22 のはずが 25 |

残った 3 件のうち policy-01 の旧本文はこれである（実測 20:13 のログより）:

> …⚠️ これは法令違反ではなく社内整合性の指摘である。**法令が定める既定値どおりの表示
> （例: 返品期限 8 日）は、それ自体は適法である。**

これは #96 で「8 日という表示そのものを免責する読み方ができる」として書き替えた文である。
残したまま RAG に引かせると、**修正前の挙動が復活しうる。**

### 影響範囲（誰がこのコレクションを引くか）

| ルール | 検索先 |
|---|---|
| policy-01 | `ec_policy_anthropic` のみ（#95 で限定） |
| 残り 21 件 | 既定スコープ = `ec_ad_rules_anthropic` + `ec_policy_anthropic` |

policy-01 自身は影響を受けないが、**21 件の条文ルールは古い行を引きうる**。
#98 以降は判定基準（コード側・最新）と規程（Qdrant 側・古い）を両方受け取るため、
両者が食い違うと LLM に矛盾した入力を渡すことになる。

## 7. この調査で学んだこと（同じ轍を踏まないために）

1. **「宣言」と「実装」は別物。** `rulesets.py` は「プロンプトへ埋め込む」と 2 箇所で
   書いていたが、実装は渡していなかった。docstring を根拠にしない。`grep` で確かめる。
2. **偶然動いていたものは、正しい修正で壊れる。** #95 は検索精度を上げた正しい修正だが、
   同時に判定基準の唯一の伝達経路を塞いだ。「良くしたのに悪化した」ときは、
   **前は何で動いていたのか**を疑う。
3. **効かない修正を繰り返したら、届いているかを確かめる。** #96 で文言を書き替えて
   挙動が 1 mm も変わらなかった時点で、「文言が悪い」ではなく「届いていない」を
   疑うべきだった。
4. **サンプルのラベルは製品の一部。** 「OK 例」が 4 件の指摘を出す状態は、
   製品の不具合と区別がつかない（#97）。検証が何度も空転した。
